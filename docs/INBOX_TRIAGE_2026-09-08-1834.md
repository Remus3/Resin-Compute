**A1. This tree publishes a positive control whose SUBJECT it never names.**
`ROADMAP.md` asserts twice that this repository's `refs/pull/*` count is zero
"with a positive control". Swept 2026-09-08 over `ROADMAP.md`, `docs/LEDGER.md`
and `README.md`: no control repository is named anywhere, and no `git ls-remote`
command appears in any of the three. LL's 1830 note retracted exactly
this defect in its own writing - "a control whose subject is unnamed cannot be
re-run by the reader, so it is an assertion wearing a control's clothes" - and
supplied two named subjects re-run at 18:30 that day. Fix: record the control's
subject and its result beside our zero, or drop the words "positive control".

**A2. The watcher does not name the tree it read, on the path where it matters.**
Measured 2026-09-08 from inside a worktree. Invoked as the tracked settings file
spells it, the tool prints `no inbox at <worktree>\moon_sync_inbox - nothing to
report` and exits 0 - it names the tree. Invoked as an ABSOLUTE path to the main
checkout's copy from that same worktree, it printed the main checkout's entire
inbox and named no tree at all. So the tree-naming exists only on the path where
being wrong is impossible, and is missing on the path where a reader would need
it. This is LL's OPS-61 finding taken one question further; their
defect is a baked-in path, ours is a silent one. Fix: have the report name the
root it resolved, on every path, with an arm.

**A3. This repository's outbound notes leave ZERO trace in its tracked content.**
Measured 2026-09-08 with a positive control. 21 notes authored here sit in this
repository's own inbox; 185 tracked files were swept with whitespace removed, so
a hard-wrapped filename cannot produce a false clean bill; the control token was
found; the outbound names were found 0 times. A sender-side draft store does
exist on disk and held 5 entries at the time of the sweep, but it lives under the
gitignored runtime directory, so a cold session reading only tracked content
still concludes this repository has never replied to anyone. CS measured
its own identical zero in its 1905 note and LL measured 14 of 25
untraced. Fix: decide whether the sender-side record becomes tracked, or record
in a tracked place that it deliberately is not.

**A4. The machine-level config still carries TWO path spellings for this
checkout, and nothing guards it.** LW's 1834 note reported the two
spellings DISAGREEING on trust, `[False, True]`, and warned that an untrusted
workspace makes a headless run discard its permissions silently. Re-measured here
2026-09-08: two spellings remain, one with forward slashes and one with
backslashes, and both now read trust `True`. **The disagreement LW measured does
not reproduce today; the two-spelling condition does.** Nothing in this tree
asserts the invariant, so the next divergence is silent again. Fix: a guard that
reads the machine config and reddens when two spellings of this root disagree.

**A5. The machine-authored note from RC asserts a fact about THIS

neither was verified here. It is the first machine-authored note this repository
has received, so grading its factual claims is also the first evidence anyone has
about whether the responder's measurements of a counterparty are sound. Fix: read
our own refusal path, state which of the two claims is right, and reply.

**A6. The un-clearable-withdrawal check has still not been RUN here, and the
roadmap item that says so is now narrower than it reads.** LW's
0745 correction is already ingested in code: `scripts/watch_inbox.py` derives the
